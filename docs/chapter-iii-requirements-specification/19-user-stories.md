# Capítulo III: Requirements Specification

En este capítulo se presentan los requisitos de **StorePulse**, definidos a partir de las necesidades identificadas para
los principales actores involucrados en la gestión y operación de galerías comerciales, principalmente los
**administradores de galerías** y los **inquilinos de los locales comerciales**, así como los visitantes interesados en
conocer la solución.

A partir de estas necesidades, los requisitos se organizan de manera progresiva para representar tanto las
funcionalidades que ofrece StorePulse como los aspectos técnicos necesarios para su implementación. Para ello, se
emplean diferentes tipos de **Stories**, que permiten describir las necesidades desde la perspectiva del usuario, del
equipo técnico y de los dispositivos IoT.

Asimismo, se presenta el **Impact Mapping**, utilizado para relacionar los objetivos del producto con los actores
involucrados, los impactos que se busca generar y las funcionalidades necesarias para alcanzarlos. Esta representación
permite mantener una relación clara entre las necesidades del negocio y las funcionalidades propuestas para StorePulse.

Finalmente, los requisitos identificados se consolidan en el **Product Backlog**, donde las Stories se organizan y
priorizan para establecer una visión estructurada del trabajo que requiere el producto. De esta manera, el capítulo
permite comprender cómo las necesidades identificadas durante el análisis se transforman en requisitos concretos y
trazables que orientan el desarrollo de StorePulse.

## 3.1. User Stories

Para el presente proyecto, los requerimientos se organizaron mediante una estructura jerárquica que permite representar
las necesidades del producto desde una perspectiva general hasta aspectos funcionales y técnicos más específicos.

En primer lugar, se definieron los **Epics**, que representan grandes áreas funcionales del sistema y agrupan un
conjunto de necesidades relacionadas. Estos permiten delimitar el alcance del producto y organizar las funcionalidades
según los principales objetivos de StorePulse.

A partir de cada Epic se descomponen diferentes tipos de **Stories**, según el propósito y el actor involucrado:

* **Visitor Stories (VS):** representan las necesidades de los visitantes que interactúan con el sitio informativo de
  StorePulse antes de utilizar la plataforma.
* **User Stories (US):** representan las necesidades y funcionalidades que los usuarios finales, principalmente
  administradores e inquilinos, requieren para realizar sus actividades dentro de la plataforma.
* **Technical Stories (TS):** representan necesidades técnicas relacionadas con el desarrollo del backend, APIs,
  procesamiento de información y servicios que permiten soportar las funcionalidades del sistema.
* **Maker Stories (MS):** representan necesidades asociadas al comportamiento y funcionamiento de los dispositivos IoT,
  incluyendo sensores, identificación, telemetría y almacenamiento local.
* **Spike Stories (SP):** representan investigaciones técnicas o de viabilidad que deben realizarse antes de implementar
  determinadas funcionalidades, permitiendo reducir incertidumbres y tomar decisiones fundamentadas sobre tecnologías y
  soluciones.

Esta organización permite relacionar las necesidades del negocio con las funcionalidades que percibe el usuario y con
los componentes técnicos que hacen posible su implementación. De esta manera, los **Epics** establecen el contexto
general, mientras que las diferentes **Stories** permiten descomponer progresivamente cada necesidad en elementos
concretos que pueden ser analizados, priorizados, desarrollados y validados.
